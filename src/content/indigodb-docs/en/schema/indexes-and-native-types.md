Beyond core tables and foreign keys, `.indigo` models PostgreSQL-specific physical storage types, access methods, Row-Level Security (RLS) policies, and column-filtered logical replication.

## Native Type Overrides (`@db.*`)

Use `@db.<Type>` when the default scalar mapping (`text`, `numeric`, etc.) needs a narrower PostgreSQL column type. The compiler checks compatibility and argument arity strictly:

| Attribute | Compatible Scalars | Arity | Emitted PostgreSQL DDL |
| :--- | :--- | :--- | :--- |
| `@db.VarChar(n)` | `String` | 1 integer | `VARCHAR(n)` |
| `@db.Uuid` | `String` | 0 arguments | `UUID` |
| `@db.Numeric` / `@db.Numeric(p, s)` | `Decimal`, `Float` | 0 or 2 integers | `NUMERIC` or `NUMERIC(p,s)` |

```indigo
Table Product {
  id    String  @id @db.Uuid @default(uuid())
  sku   String  @unique @db.VarChar(64)
  price Decimal @db.Numeric(12, 2)
}
```

> Precedence rule: If a column uses `@default(autoincrement())`, the `GENERATED BY DEFAULT AS IDENTITY` base type (`integer` or `bigint`) takes precedence over `@db.*`.

## Indexes (`@@index` & `@@unique`)

Both `@@index` and `@@unique` accept an array of schema field names (or `[]` for expression indexes) plus optional named arguments: `name`, `type`, `where`, and `expression`.

### Named & Typed Indexes

```indigo
Table Article {
  id       String @id @db.Uuid
  slug     String
  tags     Json
  location String

  @@index([slug], name: "article_slug_hash_idx", type: hash)
  @@index([tags], type: gin)
  @@unique([slug], name: "article_slug_key", type: btree)
}
```

- **Allowed `type:` values**: `btree` (default), `gin`, `gist`, `hash`.
- **`@@unique` restriction**: Unique indexes only support `btree` (`type: gin` on `@@unique` fails validation).
- **PostgreSQL identifier limit**: Explicit `name:` strings must be 1–63 bytes (`NAMEDATALEN`) without quotes or control characters and cannot collide with explicit or auto-derived names (`<table>_<cols>_idx` / `<table>_<cols>_key`) on the same table.

### Partial & Expression Indexes

Use `where:` for partial indexes and `expression:` (with an empty `[]` column array and a required explicit `name:`) for expression indexes:

```indigo
Table Account {
  id        Int       @id @default(autoincrement())
  email     String
  deletedAt DateTime? @map("deleted_at")
  metadata  Json

  // Partial index on active accounts only
  @@index([email], where: "deleted_at IS NULL")

  // Partial unique constraint
  @@unique([email], name: "account_active_email_key", where: "deleted_at IS NULL")

  // Expression index (must pass [] and explicit name:)
  @@index([], name: "account_lower_email_idx", expression: "lower(email)")

  // Combined partial + expression unique index
  @@unique([], name: "account_active_lower_email_key", expression: "lower(email)", where: "deleted_at IS NULL")

  // JSONB expression GIN index
  @@index([], name: "account_meta_tags_gin", type: gin, expression: "(metadata -> 'tags')")
}
```

> **TypeScript client note**: Partial and expression unique indexes are excluded from `ModelWhereUniqueInput` and `upsert` conflict targets because PostgreSQL cannot target a filtered `WHERE` predicate with an unconditional `ON CONFLICT (cols)` clause.

## Declarative Row-Level Security (`@@allow`)

Declare tenant or owner isolation rules directly on a `Table` block using `@@allow(action, condition)`:

```indigo
Table Document {
  id       Int     @id @default(autoincrement())
  title    String
  ownerId  Int     @map("owner_id")
  isPublic Boolean @default(false) @map("is_public")

  @@allow(read, auth.userId == this.ownerId)
  @@allow(read, this.isPublic == true)
  @@allow([create, update, delete], auth.userId == this.ownerId)
}
```

### Grammar & Expansion Rules

- **Actions**: Canonical actions are `read`, `create`, `update`, and `delete` (single identifier or array `[create, update]`).
- **Convenience aliases**:
  - `write` expands at compile time into `create`, `update`, and `delete`.
  - `all` expands into `create`, `read`, `update`, and `delete`.
- **Multiple rules for the same action**: Combined with PostgreSQL native `OR` semantics across `CREATE POLICY` statements.
- **Condition operands**: Supports `==` equality between `this.<field>` (resolved to physical `dbName`), `auth.userId`, or literal `string` / `number` / `boolean` values.

### How IndigoDB Enforces `@@allow` in PostgreSQL

1. `@indigodb/migrator` emits `ALTER TABLE ... ENABLE ROW LEVEL SECURITY;`, `ALTER TABLE ... FORCE ROW LEVEL SECURITY;`, and scoped `CREATE POLICY` statements reading `current_setting('app.user_id', true)`.
2. The migrator derives the exact SQL cast (`::integer`, `::uuid`, `::text`, etc.) from `columnSqlType(column)` automatically.
3. In your backend, [`db.$auth({ userId }, async (tx) => ...)`](/indigodb/orm/transactions-rls-and-adapters#row-level-security-with-auth) opens a dedicated transaction and binds `SELECT set_config('app.user_id', $1, true)` (transaction-local, parameterized) so connection pools never leak identity across requests.

## Realtime Column Projection (`@@realtime`)

Mark any table with an `@id` primary key as `@@realtime` to stream changes through `@indigodb/realtime`:

```indigo
Table User {
  id           String @id @db.Uuid
  email        String @map("email_address")
  passwordHash String
  status       String

  // Only emit id and email in change/log payloads; passwordHash is stripped before fan-out
  @@realtime(columns: [id, email])
}
```

- **Bare `@@realtime`**: Streams all columns in `new` / `old` payloads (on `GET /api/realtime/log` and in-process `engine.on("change")`).
- **Projected `@@realtime(columns: [...])`**: Narrows `new` and `old` at write time inside `WalSource` / `PgNotifySource` before events reach the log table or listeners. Unlisted sensitive fields (and future columns added later) are excluded fail-closed.
- **Identity-only `@@realtime(columns: [])`**: Valid syntax; keeps only `pk` and emits empty `new` / `old` field maps.
