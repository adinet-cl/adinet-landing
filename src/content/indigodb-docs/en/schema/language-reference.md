Every IndigoDB project centers on a `.indigo` schema file (typically `schema.indigo`). The language combines **dbdiagram-style `Table` and `TableGroup` blocks** with **Prisma-style `@` and `@@` attributes** so ORM typing, migrations, ERD diagrams, and documentation share one definition.

## Top-Level Blocks

A `.indigo` schema supports five top-level declarations:

1. `datasource`: Database connection configuration.
2. `generator`: TypeScript ORM code generation target.
3. `enum`: Named PostgreSQL enum definitions.
4. `Table`: Model/table definitions with columns, relations, indexes, RLS, and realtime directives.
5. `TableGroup`: Named, colored visual clusters for the Studio ER diagram.

Comments use `//` for single-line annotations.

## `datasource` & `generator`

IndigoDB currently targets **PostgreSQL** (`provider = "postgresql"` is validated by the compiler):

```indigo
datasource db {
  provider = "postgresql"
  url = env("DATABASE_URL")
}

generator client {
  provider = "indigodb-client-ts"
  output = "src/generated/indigo.ts"
}
```

- `datasource.url` accepts either `env("ENV_VAR_NAME")` (recommended) or a literal connection string.
- `generator.output` specifies where `indigodb generate` emits the TypeScript client (defaults to `src/generated/indigo.ts` if omitted).

## Scalar Types & Dialect Mappings

IndigoDB supports nine built-in scalar types defined in [`@indigodb/ast`](https://www.npmjs.com/package/@indigodb/ast) (`ScalarType`):

| `.indigo` Type | PostgreSQL Default DDL | TypeScript Generated Type | Notes |
| :--- | :--- | :--- | :--- |
| `String` | `text` | `string` | Override length/UUID with `@db.VarChar(n)` or `@db.Uuid` |
| `Int` | `integer` | `number` | With `@default(autoincrement())` emits `integer GENERATED BY DEFAULT AS IDENTITY` |
| `BigInt` | `bigint` | `string` | Mapped to JS `string` to match `pg` int8 parser precision |
| `Float` | `double precision` | `number` | Supports `@db.Numeric` / `@db.Numeric(p, s)` override |
| `Decimal` | `numeric` | `string` | Supports `@db.Numeric` / `@db.Numeric(p, s)`; string preserves arbitrary precision |
| `Boolean` | `boolean` | `boolean` | Literal defaults `@default(true)` / `@default(false)` |
| `DateTime` | `timestamptz` | `Date` | Supports `@default(now())` (`DEFAULT now()`) |
| `Json` | `jsonb` | `unknown` | Supports `JsonFilter` (`path`, `jsonContains`) in client `where` |
| `Bytes` | `bytea` | `Buffer` | Binary byte payloads |

### Field Modifiers

- **Optional / Nullable (`?`)**: `bio String?` emits nullable SQL columns and `string | null` in TypeScript.
- **List (`[]`)**: Used for to-many relation fields (for example `posts Post[]`).

## Enums & Value Mapping

Enums compile into PostgreSQL `CREATE TYPE ... AS ENUM (...)` declarations and TypeScript string literal unions:

```indigo
enum OrderStatus {
  PENDING   @map("pending")
  PAID      @map("paid")
  CANCELLED @map("cancelled")
}
```

- `@map("...")` on an enum member separates the TypeScript identifier (`PENDING`) from the physical PostgreSQL enum label (`'pending'`).
- In `migrator` and `generator`, enum defaults (`@default(PENDING)`) automatically resolve to their mapped physical label (`'pending'::"OrderStatus"`).

## Field Attributes

Only recognized attributes from the compiler's strict whitelist (`crates/indigo-compiler/src/rules.rs`) are accepted—unknown attributes or misspelled arguments fail validation immediately with 1-based line and column diagnostics.

| Attribute | Target | Description |
| :--- | :--- | :--- |
| `@id` | Scalar / Enum field | Marks the primary key column. Repeat `@id` on multiple fields for a composite PK |
| `@unique` | Scalar / Enum field | Enforces a single-column `UNIQUE` index (`<table>_<col>_key`) |
| `@default(expr)` | Scalar / Enum field | Accepts literals (`"x"`, `0`, `true`), enum members (`USER`), or generator functions: `autoincrement()`, `now()`, `uuid()`, `cuid()` |
| `@map("col_name")` | Field | Maps a camelCase TypeScript field (e.g. `createdAt`) to a physical PostgreSQL column (`created_at`) |
| `@note("text")` | Field | Documentation note rendered in Studio's Docs Browser and ERD inspector |
| `@relation(...)` | Model field | Declares a foreign key relationship (see below) |
| `@db.<Type>(...)` | Scalar field | PostgreSQL native type override (`@db.VarChar(n)`, `@db.Uuid`, `@db.Numeric`) |

> Note on `@default(cuid())`: `cuid()` is recognized by the schema compiler as a valid generator function with no SQL `DEFAULT` clause (intended for app-side generation). `@default(uuid())` emits PostgreSQL `DEFAULT gen_random_uuid()`, and `@default(autoincrement())` emits `GENERATED BY DEFAULT AS IDENTITY`.

## Relations & Referential Actions

Declare the foreign-key holder side with `@relation(fields: [...], references: [...])` and the inverse side with the target model type:

```indigo
Table User {
  id      Int      @id @default(autoincrement())
  profile Profile?
  posts   Post[]
}

Table Profile {
  id     Int    @id @default(autoincrement())
  userId Int    @unique @map("user_id")
  user   User   @relation(fields: [userId], references: [id], onDelete: Cascade)
}

Table Post {
  id       Int    @id @default(autoincrement())
  authorId Int    @map("author_id")
  author   User   @relation(fields: [authorId], references: [id], onDelete: Restrict, onUpdate: Cascade)

  @@index([authorId])
}
```

### Disambiguating Multiple Relations

When two models share more than one relation, name each pair explicitly with a leading string literal in `@relation("Name", ...)`:

```indigo
Table User {
  id            Int    @id @default(autoincrement())
  authoredPosts Post[] @relation("Author")
  reviewedPosts Post[] @relation("Reviewer")
}

Table Post {
  id         Int   @id @default(autoincrement())
  authorId   Int
  reviewerId Int?
  author     User  @relation("Author", fields: [authorId], references: [id])
  reviewer   User? @relation("Reviewer", fields: [reviewerId], references: [id], onDelete: SetNull)
}
```

### Supported Referential Actions

Both `onDelete` and `onUpdate` accept the exact PascalCase Prisma vocabulary:

| Schema Spelling | PostgreSQL DDL |
| :--- | :--- |
| `Cascade` | `CASCADE` |
| `Restrict` | `RESTRICT` |
| `SetNull` | `SET NULL` |
| `SetDefault` | `SET DEFAULT` |
| `NoAction` | `NO ACTION` |

> Note: The compiler resolves both `onDelete` and `onUpdate` into `ForeignKey` IR, while `@indigodb/migrator` currently renders `ON DELETE` DDL directly in migrations and `db push`.

## Model (`Table`) Block Attributes

| Attribute | Description |
| :--- | :--- |
| `@@map("table_name")` | Maps PascalCase model name (e.g. `UserProfile`) to physical table `user_profiles` |
| `@@note("text")` | Model-level documentation note displayed in Studio's Docs Browser |
| `@@index([...], ...)` | Secondary index (supports `name:`, `type:`, `where:`, `expression:`) |
| `@@unique([...], ...)` | Composite or partial/expression unique constraint (`btree` only) |
| `@@allow(action, cond)` | Declarative PostgreSQL Row-Level Security policy (`read`, `create`, `update`, `delete`, `write`, `all`) |
| `@@realtime` / `@@realtime(columns: [...])` | Streams WAL `pgoutput` change notifications with optional column projection allowlist |

## Visual Grouping (`TableGroup`)

`TableGroup` organizes tables into color-coded domains inside IndigoDB Studio's ER Designer without affecting SQL generation:

```indigo
TableGroup "Billing & Orders" {
  color = "#38bdf8"

  Invoice
  Payment
  Subscription
}
```

Every table listed inside the block inherits `color` and `group` metadata in `ResolvedSchema`.

## Schema Printing (`printSchema`)

`@indigodb/core` exports `printSchema(resolved, options)` as the deterministic inverse of `parse` + `resolve`, used by `indigodb db pull` to format introspected PostgreSQL databases back into canonical `.indigo` text.
